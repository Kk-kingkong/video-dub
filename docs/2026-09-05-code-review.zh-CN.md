# 视频翻译插件代码与需求审查

日期：2026-09-05。对照会话：`_视频翻译插件—new`。审查基线：`6b2b068` / 0.2.5。本地修复版本：0.2.6，分支 `codex/fix-repeated-voice-playback`，尚未发布。

## 重复播放：已复现并修复

实时配音同步只检查音频是否暂停，未区分音频已经结束。如果同步循环在 `ended` 事件清理前运行，会再次调用 `play()`，上一段便从头播放。整条音轨预览已有结束判断，实时分段配音遗漏了同一判断。

复用项目现有 `tools/live_voice_media_harness.html`，在应用内 Chromium 浏览器执行“正常开始”：

| 指标 | 原版 | 修复后 |
| --- | --- | --- |
| 同一段音频的播放请求数 | 2 | 1 |
| 最终配音进度 | 0.677 秒，已从头重播 | 3.4 秒，完整播放结束 |
| 播放错误 | 无 | 无 |

修复位于 `extension/content_helpers.js` 的 `computeLiveVoiceSync`，两个调用入口均传入真实 `audio.ended`。暂停但尚未结束的音频仍可继续播放。浏览器播放结束后再次 `play()` 会回到起点，符合 [HTML 媒体规范](https://html.spec.whatwg.org/multipage/media.html#internal-play-steps)。

同时修复 `extension/content.js` 的三个异步竞争点：旧 `play` 事件不能把上一段重新标为正在播放；旧 `play()` 完成后不能同步新音频；跳转后再次请求同一段时，旧请求结束不能清空新请求的等待状态。每处都检查当前音频身份或播放代次。作废播放尝试时同步清除等待标记，保证关闭再开启配音后，同一段仍能正常重试。

这是已经确认的重复机制。尚未取得用户实际出错视频、时间点和所选音色，不能据此断言该视频的所有叠音来源都已排除。

## 另外两处已修复问题

1. **模型返回多余译文会错配字幕。** `background.js` 的 `parseTranslationArray` 原来先截成期望条数，使已有数量检查失效。例如两条字幕收到“第一段、额外重复、第二段”，直接留下前两项。现在保留完整返回，交给已有拆批重试；单条仍异常则明确报错。
2. **长视频缓存伪装成完整结果。** `background_helpers.js` 原来把 5001 条字幕截成 5000 条，下次读取仍认为命中了完整字幕。现在超上限整条不缓存；5000 条以内及其他视频缓存保持可用。播放本身不因此限制为 5000 条。

旧版字幕缓存没有可靠身份标记。本轮已把缓存内容版本升级为 v2，首次读取或写入时自动淘汰 v1 字幕条目，不触碰 API Key 和设置，无需手动清除。

## 原会话需求与后续改进

原会话的核心要求是：优先复用已有中文字幕；没有目标字幕时再翻译；“说结束的比它快，我们可以在后面进行等待”；字幕与语音匹配，暂停、拖动、倍速同步；保持 Microsoft 自然在线音色，降级必须提示且不覆盖原设置；Engine 按需启动以减少常驻资源；字幕读取希望在 30 秒内完成。

以下六项已按本轮授权落实：

| 改进 | 实现与边界 |
| --- | --- |
| 暂停与缓冲同步 | 视频 `pause` / `waiting` 事件立即暂停当前 Audio 与浏览器朗读，恢复播放时检查当前片段和代次；等待中的旧 TTS 和旧朗读回调不能抢占新片段。 |
| 缓存身份隔离 | 保留视频和模型 ID 大小写，区分手选源语言与相关 API/Engine 地址。地址去除凭证后计算摘要，缓存不保存原地址；YouTube 字幕仍可跨翻译服务复用。翻译中切换配置或临时降级时，禁止把混合结果写成另一配置的缓存。 |
| 整轨复用正确性 | 任务键纳入视频身份和实际输出时长，纯配音也遵守；无效时长被拒绝。 |
| Engine 按需启动与退出 | macOS / Windows 安装流程清理旧登录自启动。实际翻译、TTS、导出等操作在连接失败时共用一次有截止时间的唤醒与重试，状态检查不唤醒。空闲 5 分钟退出，保护请求、后台任务、模型下载和音轨下载。已完成音轨保存最小元数据，重启后在原有 1 小时保留期内仍可预览或下载。整轨播放复用已有轮询保持服务可用；暂停允许退出，恢复与跳转先确认 Engine 就绪再读取媒体。 |
| 字幕启动等待 | 页面探测与 Engine 健康检查并行，从开始探测起共用 23 秒等待截止时间；页面稍晚成功可及时返回。目标语言字幕仍优先；网络限流、视频不可访问与确实无字幕保持不同处理。23 秒约束等待阶段，不保证外部字幕服务一定成功，也不包含后续翻译、转写和语音生成。 |
| 轻量模式引导 | 无字幕时提示启动/恢复 Engine 并重试完整模式，或换有公开字幕的视频，不再引导开启当前模式不可用的转写设置。 |

优先把重复、漏播、暂停和缓存正确性稳定下来。人声分离、视频封装曾被暂缓；本轮不扩展这些功能。现有验证中大量断言只检查源码是否出现某个字符串，后续应逐步用真实行为测试替换，复用已有测试页即可。

## 验证与使用范围

- 新增播放结束、旧事件/旧请求、关闭再开启配音、译文数量恢复、缓存上限回归，均先复现失败再验证修复。
- 扩展流程、Provider 注册表、翻译完整性、JavaScript/Python 生命周期、Python Engine、Kokoro、Native Messaging、运行时打包自检、Windows 源码包检查、开源/商店元数据检查通过。
- 新增确定性行为检查覆盖页面字幕与健康检查并行、23 秒截止时间、临时降级/配置切换时的缓存身份、过期音轨及旧请求回包。真实临时端口检查覆盖健康轮询不保活、活动 HTTP 与模型任务、退出竞态；macOS 旧自启动清理通过隔离运行环境与模拟 launchctl 验证。
- 浏览器媒体测试 1 倍速播放一次；再次主动开始并切至 1.5 倍速，只增加一次播放请求，两次均停在音频末尾，没有自动重播；“运行媒体自检”返回 `selfTest.passed: true`，覆盖晚启动、倍速计算与显式跳转。
- 未执行用户实际视频的听感验证、Windows 实机安装、商店发布或 GitHub 推送；本轮包含 Engine 与安装器改动，需要更新 Engine 才能应用按需退出和整轨复用修复。

本地使用：在 Chrome 扩展管理页重新加载源码目录 `extension/`，刷新现有 YouTube 页面。旧字幕缓存会自动迁移。商店安装的扩展不会因本地文件修改而自动更新；若用源码版验证，同一个页面只启用一个 LocalTube Dub 版本，以免两个实例同时配音。

Engine 使用范围：本轮只更新项目源码和安装流程，没有替换用户已安装的 Engine、修改 Chrome 配置或发布新安装包。源码版可按 companion/README.md 重新执行 Native Host 安装以部署更新的运行环境；商店用户需要后续发布的匹配版本。
